# Project handoff

- **Source version:** v1.3.3, the SF1+ edition of Street Fighter: The World Tournament. The Main Menu shows the edition prime and subtitle with extra spacing. Windows uses the Ryu icon for the executable and game window.
- **Stronger Fair CPU (spec #192; SC1 #193, SC2 #194 and SC3 #195 built 2026-11-18 and 19, not pushed, tickets open):** **The switch** is `MatchConfig::stronger_cpu`, off everywhere; the `--stronger-cpu` launch flag of `sf-game` turns it on through `GameSession::with_stronger_cpu`, and no menu does. It is not sent to a netplay peer, so the session keeps it off online until SC14 (#206), and Dramatic Battle's CPUs ignore it until SC23 (#215). The replay file does not record it, so a fight played with it on stays in the session's replay list but is not written to disk; whether to add it to the replay format is an open question for the maintainer. **With it on** the Fair CPU judges one of eight situations plus a corner flag from the frame its reaction delay shows it (`fair_cpu/game.rs`, `Situation`, `Judged`), and Ryu in the SF6 era style follows one game plan in close neutral: walk to crouching medium kick range, press it, then a projectile after a hit it sees, a walk-in throw after a guard, or giving ground and guarding after a whiff. A game plan is a table of steps, each naming the step that follows a hit, a guard, a whiff, a jump or nothing; the CPU's state holds only where it is in one. A threat it answers, or being hit, ends the plan. While a plan is followed the Utility AI adds no command (for SF2 to SF6 styles it otherwise takes the pad on any frame the Fair CPU's pad is empty, which is what SC8 #200 removes). Pairs with no game plan play as before. Tests: `tests/stronger_cpu.rs` (five fight tests on the bare machine) and unit tests in `fair_cpu/game.rs`; the 13 tests of `tests/fair_cpu.rs` pass unchanged with the switch off. The canonical tags `FairCpu.v1` and `PowerOnGameplay.v2` became `v2` and `v3`, so state hashes differ from older builds even with the switch off; play does not. Things measured, not designed: the walls at x 114 and 400 (Ryu walked into both on Training's stage; other stages unchecked) and a knockdown read as a hit reaction drawn off the ground. **The measuring run** (SC1) plays headless matches with the Fair CPU on both pads: `cargo run -p sf-host --release --example cpu_measure -- <out.tsv> <p1> <p1 style> <old|new> <p2> <p2 style> <old|new> <level> <first seed> <count> [threads]` (for example `ryu sf6 new ryu sf6 old 4 1 60`). `sf_engine::measure` does the counting and its module docs say what each number means and where it is approximate. Player 1's Fair CPU is a second one the machine holds only for this run (`p1_fair_cpu`). Numbers, 60 Ryu SF6 mirror matches at Very Difficult, seeds 1 to 60. Old against old: about 77 attacks started a minute, idle 21% of live frames, 1.12 hits and 8.0 health bar points an opening, a hit followed up in 9% of openings, Player 2 winning 34. New against old with SC2 alone: the new side won 27 of 60 on either pad, with about the same activity. The first game plan does not make the CPU stronger by itself; that is expected before routes (SC4 #196). Not verified: nobody has played against the switch, any pair other than the Ryu SF6 mirror, the bosses' tables in the measuring run, and the measuring run's hit, chip and round-winner counting against a watched match.
- **Route books (SC3 #195, built 2026-11-19, not pushed, ticket open):** `sf_engine::route_book` holds the route book format, its loader, the reference positions, the replay that proves a route, and the widened search. A book is a text file per tournament fighter and era style in `crates/sf-engine/route-books/`, compiled in with `include_str!` and listed in `route_book::BOOKS`; `route_book::book(fighter, revision, loadout)` returns it. Ryu's SF6 book has 20 routes: on the ground a raw Super Art and nine normal-into-Hadoken cancels of two hits, and as punishes ten routes of two to eight hits. `cargo run -p sf-host --release --example route_search -- <fighter> <style> [nodes] [keep]` regenerates a book in about a minute. `tests/route_books.rs` replays every route of every checked-in book against the reference defender (Ryu), checks hits, damage, meter and knockdown, and each step at both ends of its window; a moveset change that breaks a route fails it until the book is searched again. A route is the pads to enter, for an attacker on the left facing right, as steps with a wait before each and the window that wait may vary in. A step is named by its input, not by the move it gave. The engine's combo count is only written on a hit and restarts at 1 on a hit outside hitstun, so the search and the replay treat a hit that does not raise it by one as a dropped combo; the first version missed that and recorded dropped combos as routes. **Not met:** the search found no route from a jump-in for Ryu in SF6, although jump-in openers land; whether the engine lets a grounded hit continue a jump-in's count is not known. No route's first cancel can be confirmed (`confirm` is 0 on all): every two-step route is a cancel that must be committed before the hit shows. **Approximate or unchecked:** meter gained is measured from full meters, so it undercounts, and a punish's Drive gain includes what guarding the sweep gave back; knockdown is read from how the defender is drawn after the last hit and nobody has watched a route; the rules a route needs are structural for era styles (any second hit needs true combos, a button during an attack needs cancels), because an era style forces both rules on whatever the switches say; every route was found away from the corner, so none is marked as needing it and corner-only routes are not searched; anti-air and Drive Rush starts are in the format with nothing filling them; a boss's book needs the art pack's data bank, which the proof test does not pass yet (SC13 #205). The Fair CPU does not read the book yet (SC4 #196), and it is not yet part of what a netplay session agrees on (SC14 #206).
- **Linux build (#125, open):** `sf-game` builds for x86_64 Linux and the **Linux release** workflow (manual runs only, artifact only, nothing published on a tag) packages `sf1-port-vX.Y.Z-linux-x86_64.tar.gz` with its SHA-256 sidecar. The runtime baseline is Ubuntu 22.04 (glibc 2.35): `tools/release/build-linux.sh` builds inside an `ubuntu:22.04` container, `package-linux.py` and `verify-linux-package.py` package and check the archive, and `check-linux-launch.sh` launches it as an ordinary user in a second clean container (see `tools/release/README.md`). The player's folder is `~/.local/share/sf1-port` on Linux (`sf_engine::user_folder`), ROM file names in a folder are matched in any letter case, and `sf-game smoke` opens the art and voice packs. The hosted run at `6326566` passed all of that on a virtual display with software Vulkan and no ROM set, where the smoke check's fullscreen switch and two looks' pacing fail. Not checked: real graphics drivers, Wayland, sound, controllers and a full fight on Linux; those need a desktop or the Steam Deck (#129) before #125 closes or a tag publishes the archive. The clipboard is Windows-only; hosts without a file picker get the game's ROM browser (#129). `package-windows.ps1` still hard-codes the pre-ADR-0022 edition name and strips `.git` from anywhere in a repository URL; the Linux port fixed both for itself.

- **Pause box (2026-11-18, with #237):** every pause box sits one text row higher and its rows run play, then display, quit last: `RESUME`, `MOVES`, (`RESTART ROUND` | `TRAINING`, `RESET POSITIONS`), `OVERLAYS`, `LOOK`, `GAUGE ART`, `GAUGE LAYOUT`, `QUIT TO MENU`. `MOVES` is no longer the last row, whatever older design docs say.
